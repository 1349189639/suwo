# 塑我 · 热量账本（v0.5 / PWA）

> 一句话：记录吃进去与消耗掉的，用中间那个会变胖变瘦的小人给你反馈。
> 这是《健身app开发.txt》原始诉求的**第一个可运行版本**，按《健身App_评审与下一步_v2.md》的范围裁出来。

## 怎么跑

```bash
cd app
npm install
npm run dev       # http://127.0.0.1:5178
npm run build     # 产物在 dist/
npm test          # 41 个领域层单测
```

> 本机（Windows + 沙箱）下 Vite 需要 `--configLoader native` 才能加载配置文件，
> 已写进 package.json 的 scripts，不用额外加参数。

**在手机上看**：开发时用手机访问 `http://<电脑局域网IP>:5178`；
正式用时 `npm run build` 把 `dist/` 丢到任意静态托管（Vercel/Netlify/自己的服务器），
Safari 或 Chrome 打开后「添加到主屏幕」，就是全屏无地址栏的准原生体验。

**演示数据**（不想手动录 7 天时）：

| 参数 | 效果 |
|---|---|
| `?demo=1` | 载入一份正常体型的 7 天演示数据 |
| `?demo=1&tab=stats` | 直接打开周报 |
| `?demo=1&sheet=food` | 直接打开记饮食面板 |
| `?demo=1&heavy=1` | 载入 BMI 30 的演示数据，用来看"变胖"形态 |

已有真实数据时不会被覆盖。

## 几个刻意的设计决定（和 v1 规划不一样的地方）

1. **步数不计入"今天还能吃"。**
   活动系数里已经包含日常走动，再把步数折算成热量加回去就是重复计算。
   步数只进自律指数的活动分。这是准确性的取舍，牺牲一点"我走路能多吃"的爽感。

2. **体型跟体重走，不跟自律指数走。**
   自律指数只驱动表情、姿态、精神值。体重用 7 日指数平滑后再映射体型，
   所以一次暴食不会让小人立刻变胖，一次断更也不会。

3. **未记录 ≠ 放纵。**
   没有饮食记录的日子返回 `null`，不进周均值、不扣分、不断签（今天还没记时从昨天算起）。
   被冤枉变胖是留存杀手。

4. **减脂缺口有边界。**
   按期限反推的缺口被夹在 250–750 kcal，且不低于女性 1200 / 男性 1500 kcal。

5. **小人不用任何美术资源。**
   躯干是参数化贝塞尔路径，肩宽/腰宽/臀宽由 BMI 连续插值，腹肌透明度由肌肉量驱动。
   好处：改一版不用重新出图，体型是连续的而不是 5 张图切换。
   代价：风格偏"手办"，等验证完再考虑换 Spine 或立绘。

6. **先网页不先原生。**
   省掉软著、APP 备案、应用商店审核（合计 2–4 个月），改一版刷新即可。
   代价是拿不到计步传感器——所以步数先手输。要原生能力时用 Capacitor 套壳，同一套代码不用重写。

## 公式口径

```
BMI = kg / m²        中国标准：<18.5 偏瘦 | 18.5–23.9 正常 | 24–27.9 超重 | ≥28 肥胖
BMR  Mifflin-St Jeor  男 10w+6.25h-5a+5 ｜ 女 10w+6.25h-5a-161
TDEE = BMR × 1.2 / 1.375 / 1.55 / 1.725
目标 = TDEE − 缺口（或 + 盈余）      缺口 250–750，下限 女 1200 / 男 1500
蛋白 = 1.8 g/kg（减脂）｜ 2.0（增重）｜ 1.4（保持）
步数消耗 ≈ 体重 × 0.0005 × 步数
有氧消耗 = MET × 体重 × 小时      力量 ≈ 5 MET × 体重 × 小时（每组按 3 分钟估）
自律指数 = 0.5×热量分 + 0.3×蛋白分 + 0.2×活动分
热量分：目标 ±10% 满分，偏离 40% 归零，中间线性（吃太少同样扣分）
```

## 已知限制

- 食物热量是**常见做法的参考值**，实际随品牌、油量、份量浮动 20% 以上，界面上已标注。
- 网页读不到手机计步传感器，步数需要手输。
- 数据只在这台设备的浏览器里，清缓存会丢——请定期用「我的 → 导出备份」。
- 单用户、无账号体系，换设备需要手动导入。
- 小人是示意性身材，不追求解剖准确。
